# Decision-ready handoffs

Use this for a substantive prepared artifact or an actual pending decision,
not every progress update. A card is a compact message, not a new application.

Include the information needed to decide without reopening the conversation:

1. **Outcome and location:** product, target and why the prepared work matters.
2. **Artifact:** link the exact diff, draft or evidence. Show incoming context
   beside a reply. For code, identify the revision and test result; for a visual
   decision, show the actual alternatives required by design-workflow.
3. **Recommendation and limits:** what is observed, what remains uncertain,
   meaningful cost/risk, and the smallest useful next step.
4. **Decision, if needed:** name the exact action, target, scope and consequence.
   Omit approval requests when the task is complete or execution is already
   clearly authorized within unchanged scope.

Example shape (placeholders, not a live authorization):

> Product / target — Prepared result.
> Evidence: exact artifact and checks; remaining limitation.
> Recommendation: next action and consequence.
> Decision needed: specific operation on this artifact and destination.

Use an existing screenshot only when it clarifies the decision. Do not build
visual cards or dashboards as a prerequisite to ordinary work. Group duplicates;
do not invent a quota of suggestions or impact scores.

Research/report requests do not authorize local implementation. Prepare edits
only when the task permits them. Access is not authorization to inspect unrelated
mail, prompts, accounts or histories. No inferred personal profile is required.

Before an approved mutation, refresh the target and inspect whether someone
already acted. Material changes require a revised decision. If a write's outcome
is uncertain, inspect it before retrying. Keep prepared, approved, executed and
verified distinct; Skip/Improve are not send, merge or deploy approval.

Current permission and design-selection rules remain authoritative. A broad
finish request does not select a visual direction. This guide adds no scheduler,
delegation mandate, memory writes or backend-enforced approval system.
